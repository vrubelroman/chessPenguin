# Партии со сверкой по chess.com

Партии, в которых отметки нашего разбора (!! и !) сверены с Game Review chess.com. После
каждой калибровки правил (`src/features.rs`, `src/report.rs`) прогонять **все**:

```
cargo run --release -p game-review --example chesscom_check -- <stockfish>
```

- Отметки chess.com записаны в партию как NAG: `$3` — !!, `$1` — !. Других NAG здесь нет.
- Тег `ChessComMarks` — какие отметки сверялись: `"!! !"` — обе, `"!!"` — только блестящие
  (отметки ! chess.com для этой партии неизвестны, наши ! не считаются расхождением).
- Движок считает так же, как программа (фиксированный поиск разбора, `docs/decisions.md`
  2026-10-28): Stockfish 19 из ChessPenguin, 1 000 000 узлов (`SEARCH_NODES`), один поток,
  Hash 32 МБ, `ucinewgame` перед каждым поиском, процессов — по числу ЦП (до 8). Оценки
  поэтому одинаковы на любой машине. Кэш — `target/chesscom-check/v<SEARCH_VERSION>/`:
  повторный прогон после правки правил идёт без движка.
- `CP_REVIEW_NODES=N` — другое число узлов, только для подбора константы (кэш в
  `target/chesscom-check/v<версия>-N/`); программа так не считает.
- `CP_SHALLOW_NODES`, `CP_GREAT_HARD`, `CP_BRILLIANT_HARD`, `CP_GREAT_GAP`,
  `CP_BRILLIANT_GAP`, `CP_GREAT_BANS`, `CP_HARD_DEPTH` — опыты с «трудностью» хода
  (неглубокий поиск, `Hardness`; 2026-10-29, программа их пока не использует), см.
  `examples/chesscom_check.rs`. Неглубокие поиски хранятся в том же кэше.
- Новую партию от владельца — сюда же, с источником в теге `Annotator`.

## Порядок калибровки

1. Новую партию сначала добавить и прогнать **без правок правил** — это честная проверка
   (партия не участвовала в настройке). Записать: сколько !! и ! chess.com нашлось.
2. Только потом искать причины расхождений и править. Правка — общее правило о том, что
   делает ход (жертва, отыгрыш, мат), а не исключение для хода; пороги не двигать ради
   одной партии.
3. Прогнать весь набор: ничего из прежнего не должно сломаться.

Итог прогона — доля найденных !! и ! chess.com и доля наших !! и !, которые совпали с
chess.com. Числа зависят только от правил и версии поиска: калибровки 1–7 делались на
3M узлов и 12 потоках, после перехода на фиксированный поиск (1M, один поток) они
пересчитаны (`docs/decisions.md`).

## Вердикты владельца

Партии `owner-*.pgn` — без отметок chess.com: тег `OwnerPlain` перечисляет ходы (SAN), которые
владелец считает очевидными; ни «!», ни «!!» на них быть не должно. Прогон печатает такие
нарушения строкой `OWNER` и считает их в итоговой строке.
